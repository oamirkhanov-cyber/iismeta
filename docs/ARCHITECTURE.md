# Архитектура IISMETA — обзор

> Документ описывает продукт на уровне, достаточном для технической оценки.
> Реализация, нормативная база и алгоритмы подбора не раскрываются.

---

## 1. Маршрут документа

Работа идёт по одному сквозному маршруту. На каждом шаге результат сохраняется, к предыдущему шагу можно вернуться без потери правок.

### Шаг 0 — Проект

Оператор задаёт характеристики объекта: тип, конструктивные решения, условия производства работ. Эти критерии определяют, какие нормы вообще применимы, — и используются на всех дальнейших шагах.

### Шаг 1 — Ведомость объёмов работ

Загружается ВОР в любом виде: Excel, текстовый PDF, отсканированный документ. Система распознаёт таблицу, восстанавливает структуру разделов и извлекает по каждой строке: наименование, единицу измерения, объём, принадлежность к разделу.

Далее — **нормализация**: приведение формулировок проектировщика к виду, пригодному для подбора нормы. Движок делает первый проход сам и помечает всё, что предложил; оператор проверяет и подтверждает. Ручная правка доступна в любой ячейке и переживает сохранение.

### Шаг 2 — Подбор норм ШНҚ

Для каждой строки ВОР подбирается нормативная расценка. Подбор **детерминирован**: одинаковый вход даёт одинаковый выход. По каждой позиции система показывает основание выбора — сметчик проверяет логику, а не принимает результат на веру.

Там, где однозначного решения нет (проектная информация неполна), система не угадывает, а **задаёт вопрос** — предъявляет развилку оператору.

### Шаг 3 — Смета

Подобранные нормы разворачиваются в ресурсную часть — трудозатраты, машины, материалы, — рассчитывается стоимость и формируется выгрузка в рабочем формате.

## 2. Принципы, на которых построен движок

### Детерминизм как требование, а не как оптимизация

Смета — расчётный документ, у него бывают юридические последствия. Ядро подбора не должно давать разные ответы на один и тот же вход. Поэтому языковые модели применяются там, где они уместны — распознавание документов, разбор естественных формулировок, — а собственно **подбор нормы выполняется детерминированной логикой**.

### Обоснование вместо «чёрного ящика»

Каждая подобранная позиция сопровождается основанием. Сметчик, который отвечает за смету своей подписью, должен иметь возможность проверить ход рассуждения — иначе продукт непригоден для профессиональной работы.

### Человек принимает решение

Всё сделанное движком помечено визуально и требует подтверждения. Система устроена так, чтобы **молчать было дешевле, чем ошибаться**: при недостатке данных она предъявляет развилку, а не подставляет правдоподобное значение.

### Обучение на правках оператора

Правки сметчика фиксируются в журнале «было → стало». Из них извлекаются закономерности, которые улучшают первый проход движка на следующих объектах. Автоматически применяются только правила, прошедшие проверку.

---

## 3. Проверка качества

Продукт разрабатывается вместе с практикующим сметчиком. Метод проверки:

1. сметчик считает объект вручную — получается **эталон**;
2. движок считает тот же объект самостоятельно;
3. результаты сверяются позиция за позицией — по составу работ и по объёмам;
4. расхождения разбираются: каждое становится либо исправлением движка, либо задокументированным ограничением.

Эталонные сметы используются **как измерительный инструмент**: они показывают, где движок ошибается, но их содержимое не переносится в него напрямую. Иначе продукт умел бы воспроизводить проверочные примеры, но не работать на новых объектах.

## 4. Технологический контур

| Слой | Решение |
|---|---|
| Прикладной сервер | Python, FastAPI |
| Интерфейс | JavaScript, серверный рендеринг данных, работа в браузере |
| Нормативная база | SQLite, выверенная база норм ШНҚ |
| Хранилище проектов | файловое, с постоянным диском и историей правок |
| Распознавание | языковые модели с поддержкой изображений |
| Развёртывание | Docker, облачный хостинг, непрерывная поставка |

---

## 5. Что в этом документе не раскрывается

- алгоритмы подбора и ранжирования норм;
- структура и содержание нормативной базы;
- проектная документация заказчиков, использованная при разработке;
- эталонные сметы и результаты сверок по конкретным объектам.

Эти материалы составляют интеллектуальную собственность проекта, а часть из них ограничена условиями конфиденциальности с заказчиками.
